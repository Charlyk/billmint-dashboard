  <action>
1. Install posthog-js:
   ```bash
   npm install posthog-js
   ```

2. Create `src/lib/analytics/posthog.ts` — PostHog configuration module:
   - Export `isProduction` using `process.env.VERCEL_ENV === 'production'` (matches existing pattern in `src/lib/logging/axiom.ts`)
   - Export `POSTHOG_KEY` from `process.env.NEXT_PUBLIC_POSTHOG_KEY`
   - Export `POSTHOG_HOST` from `process.env.NEXT_PUBLIC_POSTHOG_HOST` with fallback to `'https://us.i.posthog.com'`
   - This is a pure config module with no 'use client' directive (values are used at init time in client component)

3. Create `src/contexts/posthog-provider.tsx` — Client-side PostHog provider:
   - Add `'use client'` directive at top
   - Import `posthog` from `posthog-js` and `PostHogProvider` from `posthog-js/react`
   - Import `useEffect` and `type ReactNode` from `react`
   - Import `isProduction`, `POSTHOG_KEY`, `POSTHOG_HOST` from `@/lib/analytics/posthog`
   - Export `PHProvider` component that:
     - Calls `posthog.init()` inside `useEffect` ONLY when `isProduction && POSTHOG_KEY` is truthy
     - PostHog init config MUST include:
       - `api_host: POSTHOG_HOST`
       - `person_profiles: 'identified_only'` (anonymous-only, no user profiles created)
       - `capture_pageview: false` (manual tracking required for App Router)
       - `capture_pageleave: true`
       - `disable_session_recording: true` (privacy: no session replays)
       - `disable_external_dependency_loading: true` (prevents hydration issues from injected scripts)
     - When NOT production or POSTHOG_KEY missing: return `<>{children}</>` (passthrough, no PostHog context)
     - When production: return `<PostHogProvider client={posthog}>{children}</PostHogProvider>`
   - CRITICAL: Never call `posthog.identify()` anywhere — this would send PII

4. Create `src/components/analytics/posthog-pageview.tsx` — Page view tracking component:
   - Add `'use client'` directive at top
   - Import `usePathname`, `useSearchParams` from `next/navigation`
   - Import `usePostHog` from `posthog-js/react`
   - Import `useEffect` from `react`
   - Export `PostHogPageView` component that:
     - Gets `pathname` from `usePathname()`
     - Gets `searchParams` from `useSearchParams()` (this requires Suspense boundary in parent)
     - Gets `posthog` from `usePostHog()`
     - In `useEffect` with deps `[pathname, searchParams, posthog]`:
       - Guard: if `pathname && posthog`, build full URL from `window.origin + pathname` + optional search params
       - Call `posthog.capture('$pageview', { $current_url: url })`
     - Returns `null` (renders nothing)
  </action>

    - `src/contexts/posthog-provider.tsx` contains `person_profiles: 'identified_only'` and `capture_pageview: false`
    - `src/components/analytics/posthog-pageview.tsx` contains `posthog.capture('$pageview'`
    - No occurrence of `posthog.identify` in any file
  </verify>
  <done>

  </done>

  <action>
1. Modify `src/app/layout.tsx` to add PostHog integration:
   - Add imports:
     - `import { Suspense } from 'react'`
     - `import { PHProvider } from '@/contexts/posthog-provider'`
     - `import { PostHogPageView } from '@/components/analytics/posthog-pageview'`
   - In the JSX body, wrap the existing `<Providers>{children}</Providers>` with `<PHProvider>`:
     ```
     <PHProvider>
       <Suspense fallback={null}>
         <PostHogPageView />
       </Suspense>
       <Providers>{children}</Providers>
     </PHProvider>
     ```
   - PHProvider is the OUTER wrapper (above Providers) because:
     - PostHog doesn't depend on auth/SWR context
     - Page views should track even on unauthenticated pages (landing, login, signup)
     - Keeps analytics separate from application state
   - The `<Suspense fallback={null}>` around PostHogPageView is REQUIRED because `useSearchParams()` requires a Suspense boundary in Next.js App Router to prevent hydration errors

2. Verify the integration doesn't break the existing layout:
   - The existing theme script, fonts, metadata, and Providers wrapper must remain unchanged
   - Only the wrapping order changes: PHProvider wraps everything inside body
  </action>

    - No hydration-related build warnings
