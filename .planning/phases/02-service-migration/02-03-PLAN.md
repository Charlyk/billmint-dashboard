   ```typescript
     log.error('Webhook signature validation failed', {
       correlationId,

     })
     throw new ValidationError('Invalid webhook signature')
   }
   ```
   NOTE: The current code uses `catch {}` with no variable. Change to `catch (err)` to capture the error for logging.

   ```typescript
   log.info('Webhook received', {
     correlationId,
     eventId: event.id,
     eventType: event.type
   })
   ```

   ```typescript
   log.info('Webhook processed', {
     correlationId,
     eventId: event.id,
     eventType: event.type,
     duration: Date.now() - startTime
   })
   ```
   Include relevant metadata per case: userId/tier for checkout, customerId/subscriptionStatus for subscription updates, customerId for deletion.

   ```typescript
   try {
     switch (event.type) { ... }

     log.error('Webhook processing failed', {
       correlationId,
       eventId: event.id,
       eventType: event.type,
       duration: Date.now() - startTime,
       error: sanitizeError(processingError)
     })
     throw processingError  // Re-throw to trigger Stripe retry
   }
   ```

**billing webhook route.ts — NO changes needed.** The route already uses handleError and the webhook function throws on failure. The Axiom transport is inherently async (fire-and-forget), so WH-02 is satisfied automatically. Do NOT add withLogging to the webhook route because it needs special handling (raw body, stripe-signature header).
