**Funnel-ready "first time" events implementation strategy:**

The events `first_project_created`, `first_timer_started`, and `first_invoice_sent` require detecting "first time" actions. Detection options:

**Option A (recommended for this plan):** Track from the client-side API wrappers by checking the onboarding stats available via the dashboard API. BUT this would require an additional API call before each create operation, which is wasteful.

**Option B (simpler, recommended):** Use PostHog's built-in "First time event" filter in the dashboard. Since we already track `project_created`, `timer_started`, and `invoice_sent`, PostHog can filter for "first time user performed this event" without separate events. This is the industry-standard approach for anonymous tracking.

**Option C (most reliable):** Add the first-time check in the server-side service layer using DB count queries. But this requires `posthog-node` for server-side tracking.

**Implementation decision:** Do NOT add `first_*` event calls in this task. Instead, add a comment in `events.ts` explaining that the `first_*` helpers exist for when server-side tracking (posthog-node) is added. In the meantime, PostHog's "First time event" filter provides identical funnel analysis capability using the existing CRUD events. This avoids unreliable client-side first-time detection (race conditions, stale counts) and unnecessary API calls.
